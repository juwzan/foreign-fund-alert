# 결정 기록

작업 중 나온 판단·논의 중, 코드 주석만으론 다음에 다시 보기 어려운 맥락을
남겨두는 문서. 새로 대화가 시작돼도(`/clear` 포함) 이 파일은 그대로 남는다.

## 파이프라인 설계 (2026-07-21)

- **스크래핑만으로 충분**: 금감원 보도자료 게시판(`list.do`/`view.do`)이 로그인/세션 없이
  완성된 HTML을 그대로 내려줌을 브라우저로 확인(별도 XHR/JSON API 없음). 그래서 KRX/ECOS처럼
  API 키가 필요한 다른 프로젝트와 달리 이 프로젝트는 `requests` + `BeautifulSoup`만으로 동작.
- **PDF/HWP를 열지 않고 dbdata div로 본문 확보**: 상세 페이지(`view.do`)의 `<div
  class="dbdata">` 안에 보도자료 요약 문단이 이미 텍스트로 들어있음을 확인. 처음엔 PDF를
  다운로드해서 첨부하는 안을 검토했는데, 사용자가 "PDF 첨부 대신 본문 내용을 메일 본문에
  넣어달라"고 해서 dbdata 파싱으로 전환 — 다운로드 실패 가능성 자체가 없어져서 더 단순하고
  안정적임. 첨부파일은 참고용 다운로드 링크로만 메일에 남김.
- **번호(no) 증가로 신규 판정**: 목록의 `번호` 컬럼이 순차 증가하고 최신 글이 최상단에 오는
  걸 확인(현재 최신=192). `report/state.json`에 `last_seen_no`만 저장해두고, 매번 1페이지만
  조회해서 `no > last_seen_no`인 행을 신규로 판단.
- **최초 실행 baseline 처리**: state.json이 없는 최초 실행은 그 시점 최신 번호를 baseline으로
  저장만 하고 메일을 보내지 않음 — 안 그러면 과거 게시글(당시 기준 192건)을 전부 "신규"로
  오인해서 스팸처럼 한꺼번에 발송하게 됨.
- **저장소를 public으로 결정**: Gmail 비밀번호/앱 비밀번호/수신 이메일은 코드가 아니라 GitHub
  Secrets에만 저장하고(`.env`는 git에 안 올라감), 워크플로 트리거를 `schedule`/
  `workflow_dispatch`만 써서 포크 PR로도 시크릿이 노출되지 않게 함 — 이 조건이면 코드/캐시가
  전부 공개돼도 민감한 정보가 새는 경로가 없다고 판단, 사용자와 논의 후 public으로 확정.
- **체크 주기**: 게시판이 월 1회만 갱신되지만, 사용자가 당일 안에 좀 더 빠르게 알림받고
  싶다고 해서 평일 하루 2회(오전 09:00·오후 15:00 KST)로 설정.

## 배포 + 실제 발송 검증 (2026-07-21)

- **gh CLI 미설치 -> 수동 생성 방식으로 진행**: 이 컴퓨터에 GitHub CLI가 없어서
  `gh repo create`를 못 씀. 사용자가 github.com/new에서 직접 public 빈 저장소
  (`juwzan/foreign-fund-alert`, README/gitignore/license 체크 안 함)를 만들고 URL을
  주면, 로컬에서 `git remote add` + `git push`만 대신 처리하는 방식으로 진행함.
- **워크플로가 처음엔 Actions에 아예 안 뜨는 현상**: 첫 push 직후 `check_new_post.yml`이
  Actions 탭 워크플로 목록에 전혀 안 보이고(`/actions/workflows/check_new_post.yml`
  접속 시 "This workflow does not exist"), 사용자 로그인 계정으로도 동일하게 확인됨.
  파일 경로/YAML 문법/기본 브랜치(master, default 맞음)/Actions 권한(Allow all로 이미
  설정됨)/BOM 유무까지 다 확인했지만 전부 정상 — 즉 코드 문제가 아니라 GitHub의 워크플로
  인덱싱 자체가 지연되는 경우였음. **해결: 워크플로 파일에 사소한 커밋(주석 한 줄 추가)을
  다시 push하니 바로 인식됨.** 나중에 이 프로젝트든 다른 프로젝트든 새 워크플로 파일을
  올렸는데 Actions 목록에 안 뜨면, 원인 파고들기 전에 먼저 이 방법(사소한 재커밋+재푸시)부터
  시도해볼 것.
- **실제 발송 검증 완료**: `report/state.json`의 `last_seen_no`를 191로 임시로 낮춰서
  push한 뒤 Actions에서 `workflow_dispatch`로 수동 실행 -> 192번 글("2026년 5월 외국인
  증권투자 동향")을 신규로 인식해 실제 이메일이 정상 도착함을 확인. 실행 후 `main.py`가
  자동으로 `last_seen_no`를 다시 192로 갱신하고, 워크플로의 커밋-백 스텝이 그 변경분을
  그대로 커밋-push함 — 별도 수동 복구 없이 정상 상태로 자연히 돌아옴.
- **평상시 동작(신규 글 없음)**: 신규 게시글이 없으면 `main.py`가 "신규 게시글 없음"
  메시지만 출력하고 이메일 발송도, `state.json` 변경도 없이 그냥 끝남 — 워크플로의
  커밋-백 스텝도 `git diff --cached --quiet`로 변경분이 없음을 확인하고 커밋을 건너뛰므로,
  평소 실행은 조용히 아무 흔적도 안 남기고 자동 종료됨.
